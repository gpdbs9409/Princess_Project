# 어드민 사이트 기능 요구사항

프린세스 다이어리 운영진용 관리자 사이트(`/admin`) 기능 정리 문서입니다.

- 주소: `https://princess-project-2026.vercel.app/admin`
- 최종 수정: 2026-08-08

---

## 1. 접근 권한

일반 서비스와 같은 서버·같은 DB를 사용합니다. 별도 서버를 두지 않고 `users` 테이블의
`role` 컬럼(USER / ADMIN)으로 운영진을 구분합니다.

- `/api/admin/**` API는 서버에서 ADMIN 권한이 없으면 차단됩니다.
- 프론트엔드 `/admin` 페이지도 ADMIN이 아니면 대시보드로 돌려보냅니다.
- 상단 내비게이션의 "관리자" 메뉴는 ADMIN 계정에만 보입니다.

### 운영진 지정 방법

`users.role` 컬럼이 유일한 기준입니다. 로그인할 때 권한을 다시 계산하지 않으므로
한 번 지정하면 그대로 유지됩니다.

- 최초 운영진 1명은 DB에서 직접 지정합니다.
  `UPDATE users SET role = 'ADMIN' WHERE nickname = '닉네임';`
- 이후 승격·강등은 API로 처리합니다. `PUT /api/admin/users/{userId}/role?role=ADMIN`

## 2. 회원 · 지원서 관리

앱 주소는 선발이 끝난 분들에게만 전달되므로, **가입한 계정은 모두 참가자로 간주**합니다.
모집 단계의 지원서는 서비스 데이터와 완전히 분리해 내부 기록용으로만 관리합니다.

| 탭 | 내용 |
|---|---|
| **기수 미배정 회원** | 가입은 했으나 아직 기수 태그가 없는 계정. 기수를 배정하면 참가자 탭으로 이동합니다. |
| **참가자** | 기수별 필터 조회. "전체 기수" 보기도 지원합니다. |
| **지원서 (내부 기록용)** | `users`와 무관한 별도 테이블. 이름·연락처·메모·상태(검토중/합격/불합격)를 수기 입력·수정·삭제합니다. |

기수는 "1기", "2기" 같은 자유 텍스트입니다. 새 기수를 시작할 때 코드 수정이 필요 없습니다.

## 3. 주간 활동 · 환급 관리 (핵심 기능)

월요일~일요일 단위로 주를 이동하며 조회합니다.

**성공일수 판정**

그날 활성화된 미션을 기준으로 계산합니다.

- 전부 완료 → 1일
- 일부만 완료 → 0.5일
- 미완료 → 0일

**환급 판정**

6일 이상 성공하면 자동으로 "환급 대상"으로 표시됩니다 (예치금 100,000원의 1/4인
25,000원 기준). 자동 판정은 어디까지나 참고용이고, 실제 지급 여부는 운영진이 체크박스로
직접 표시하며 지급일이 함께 기록됩니다.

**CSV 내보내기**

현재 보고 있는 기수·주차 화면을 그대로 CSV로 받을 수 있습니다. 엑셀에서 한글이 깨지지
않도록 처리되어 있습니다.

## 4. 주간 MVP

기수·주 단위로 MVP를 지정합니다. 같은 기수의 같은 주에 새로 지정하면 이전 MVP는 자동
교체됩니다.

> **참고**: MVP 지정 시 스탯을 올려주는 보너스는 아직 자동 적용되지 않습니다. 지정 기록만
> 남으며, 실제 점수 반영은 아래 "점수 보정"으로 직접 입력해야 합니다.

---

## 5. 점수 보정 (컴플레인 대응)

참가자별로 총점 또는 특정 자본(심리·문화·지식·경제·신체·언어·상징)에 대해 가감점을
사유와 함께 기록합니다. MVP 보너스 지급이나 채점 이의 제기 대응에 사용합니다.

롤백은 해당 보정 내역을 삭제하는 방식입니다. 값을 덮어쓰지 않고 이력 단위로 지우기
때문에 무엇을 되돌렸는지 추적할 수 있습니다.

> **참고**: 보정 내역은 현재 기록·조회용입니다. 참가자 대시보드에 보이는 점수에는 아직
> 자동 합산되지 않습니다. 실제 반영하려면 채점 엔진(`DailyRecordService`) 연동 작업이
> 추가로 필요합니다.

## 6. 아직 없는 기능 (다음 단계 후보)

- MVP 보너스 · 점수 보정을 참가자 대시보드 점수에 자동 반영
- 지원서 엑셀 업로드 (현재는 수기 입력만)
- 완주 환급(4주 전액 환급) 자동 계산
- 최종 엔딩 리포트, 엔딩 캐릭터 배정
- 닉네임 + PIN 로그인, 초대장 페이지
- 비밀번호 찾기 · 초기화 (현재는 운영진이 DB에서 수동 처리)

## 7. 운영 참고사항

**DB 마이그레이션**

운영 DB에 아래 두 스크립트를 각각 한 번씩 실행해야 합니다.

- `backend/src/main/resources/db/migration_2026_admin.sql` — 어드민 관련 테이블·컬럼
- `backend/src/main/resources/db/migration_2026_qa.sql` — QA 반영분(`goal_appearance` 컬럼)

`schema.sql`은 `DROP DATABASE`로 시작하는 최초 설치용 스크립트입니다. 운영 DB에는
절대 실행하지 마세요.

**로그인 세션**

하루 만에 세션이 풀리던 문제를 수정했습니다. JWT 유지 기간을 30일로 늘렸고, 만료 시
자동 로그아웃되도록 처리했습니다. 배포 환경에 `JWT_EXPIRATION_MINUTES`가 따로 설정되어
있다면 함께 늘려주세요.

**성능**

주간 참가자 목록 조회가 참가자 1명당 9회씩 쿼리를 날리던 구조였습니다. 주 단위로 한 번에
조회하도록 개선했습니다.

**환경변수**

`ADMIN_NICKNAMES`는 더 이상 사용하지 않습니다. 운영진 지정은 `users.role`로만 관리합니다.
배포 환경에 남아 있다면 삭제해도 됩니다.
