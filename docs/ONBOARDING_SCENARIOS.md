이 문서는 카톡/인스타 초대장 3스텝(`OnboardingBridge.tsx`, 이미 구현됨) **이후**에 이어지는

선택 · 등급 · 미션 설정 · 규칙 안내 · 첫 인증 실습.

**전제**: 이 문서에서 쓰는 번호(1~9)는 진행 순서를 나타내는 임시 번호이고, 기획서의 SC-01~12
실제 번호와는 아직 매핑하지 않았습니다 — 원본 기획서(pptx 등)를 공유해주시면 정확한 SC 번호로
맞출게요. 코드베이스에 이미 있는 것과 완전히 새로 만들어야 하는 것을 구분해서 표시했고,
비즈니스 규칙이 코드/기획서 어디에도 없어서 제가 임의로 정할 수 없는 부분은 **⚠️ 확인 필요**로
표시했습니다 (`onboardingEndings.ts`의 TODO 표시와 같은 방식).

## 1. 로그인 PIN 분기 — 이미 구현됨

**확정 (2026-08-21)**: "PIN" = 비밀번호. 즉 이 시나리오는 후보 C("신규/기존 분기")였고, 지금
`LoginPage.tsx`의 로그인/회원가입 토글(`mode: "login" | "signup"`)이 그대로 이 시나리오예요.

| 단계 | 화면/동작 | 코드 위치 |
|---|---|---|
| 1 | `OnboardingBridge` 마지막 카드("프린세스 다이어리 접속하기")를 누르면 `dismissed=true`가 되고 `/login`이 그대로 드러남 | `OnboardingBridge.tsx:152` |
| 2 | 닉네임 입력 → 로그인 시도 → 존재하지 않는 닉네임이면 자동으로 "회원가입" 유도 문구 노출 | `LoginPage.tsx:65` (`NICKNAME_NOT_FOUND`) |
| 3 | 비밀번호 틀리면 401 에러 → "비밀번호가 올바르지 않아요" | `LoginPage.tsx:67` |
| 4 | 회원가입 시 이메일(선택)·프로필 사진(선택) 추가 입력 후 가입 → 첫 프로젝트 없으면 `/stat-focus`로, 있으면 `/dashboard`로 분기 | `LoginPage.tsx:58~63` |

**남은 일**: 추가 개발 없음 — 온보딩 문서/기획서 쪽 용어를 "PIN"에서 "비밀번호"로 정정하는 것만
필요해요 (`docs/ADMIN_SITE_SPEC.md` 6번 항목의 "닉네임+PIN 로그인" 표현도 이미 완료된 이
시나리오를 가리키는 것으로 보이니 함께 정정하면 좋을 것 같아요).

## 5. 자본(아비투스) 선택 — 이미 구현됨

`SelectionWizard.tsx`(373~521행)에 이미 전체 로직이 있어요: 7자본 중 선택 + 비중(%) 합계

설정"처럼 단계를 쪼갤지 여부 ⚠️ 확인 필요.

- 규칙 요약: 정확히 3개 선택 권장(`guide.html` 기준, 코드 자체는 개수를 강제하지 않음 —
  ⚠️ 3개 미만/초과 선택 시 막을지 여부는 정책 확인 필요), 비중 합계 100% 필수.

## 6. 등급

**확정 (2026-08-21)**: ED-02 칭호 공개 — 자본별 점수를 S~D 5단계로 나누고, 자본 고유의
수식어구 + 등급별 호칭을 조립해 "칭호"를 만드는 방식. 경제 자본 1위 예시:

| 등급 | Score | 표기 |
|---|---|---|
| S | 95~100 | 막대한 자본을 축적한 대지주 **공주** |
| A | 85~94 | 막대한 자본을 축적한 대지주 **대공녀** |
| B | 70~84 | 막대한 자본을 축적한 대지주 **공녀** |
| C | 55~69 | 막대한 자본을 축적한 대지주 **영애** |
| D | 0~54 | 막대한 자본을 축적한 대지주 — **각성한 조연** |

**Score 산정 공식 (확정, 2026-08-21)**: 30일을 4주로 나눠서, 자본별로 매 주 `주간 획득 점수 ÷
주간 최대 가능 점수`(이미 있는 진행률 공식 — `DashboardPage.tsx`의 `weeklyMaxByGoal`,
`WeeklyReportResponse.statScoreTotals`와 동일)를 구하고, 그 4개 비율에 각각 25점을 곱해 더한다.

```
자본 Score = Σ (그 주 자본 진행률 × 25)   for 1주차..4주차
           = (1주차 진행률 + 2주차 진행률 + 3주차 진행률 + 4주차 진행률) × 25
```

한 주라도 진행률이 100%를 넘을 수 없으므로(기존 `min(입력값÷목표값, 1.0)` 규칙, `SCORING_LOGIC.md`
1번) 이 공식도 자연스럽게 0~100 사이로 떨어져요 — 4주 균등 가중이라 특정 한 주만 몰아서 잘해도
전체 등급이 크게 흔들리지 않는 장점도 있어요.

**아직 확인이 필요한 부분**:

| 항목 | 내용 |
|---|---|
| 나머지 6개 자본의 수식어구 | "막대한 자본을 축적한 대지주"는 경제 자본 전용 문구예요. 문화·지식·신체·언어·심리·상징 자본용 수식어구 6개가 더 필요해요 |
| `onboardingEndings.ts`와의 정합성 | 이미 만든 온보딩 브릿지 갤러리(`onboardingEndings.ts`)도 "자본 → 공주 엔딩" 구조인데, 거기는 자본당 엔딩 1개(고정 타이틀+설명)이고 여기는 자본당 등급 5단계(S~D)예요. 최종 엔딩 리포트에서 이 둘을 하나로 합칠지, 브릿지 갤러리는 예고편 성격으로 계속 별도로 둘지 확인 필요해요 |
| 어느 자본의 칭호를 보여주는지 | "경제 자본 1위 예시"라는 표현으로 볼 때 참가자가 고른 3개 자본 중 가장 점수가 높은 자본 하나로 칭호를 정하는 것 같은데, 맞는지 / 동점이면 어떻게 하는지 확인 필요 |
| 관리자 점수 보정 반영 여부 | `docs/ADMIN_SITE_SPEC.md` 5번의 "점수 보정"(컴플레인 대응용 가감점)은 아직 참가자 대시보드 점수에 자동 합산되지 않는대요 — 등급 계산에는 포함시킬지 확인 필요 |

**연동 지점**: 지금 백엔드에는 특정 주(`weekStart`) 하나만 조회하는 `getWeeklyReport`만 있고,
4주 전체를 한 번에 묶어 계산하는 API가 없어요. 새 엔드포인트(예: `GET /api/reports/final` 또는
`AdminService`에 등급 계산 메서드) 하나가 필요하고, 이건 이미 `WeeklyMvp.java`/`AdminService.java`
주석에서 "Score 산정식이 확정되기 전이라 등급 시스템도 아직 없다"고 언급된 바로 그 작업이에요 —
이제 공식이 확정됐으니 이어서 구현할 수 있어요.

## 7. 미션 설정 — 이미 구현됨

`SelectionWizard.tsx`(395~518행)에 카탈로그 기반 미션 체크/목표값/단위/배점/매일·매주 선택
로직과 "나만의 미션" 직접 추가 로직까지 모두 있어요. 검증 규칙도 이미 있어요:

- 목표값 범위: `MIN_MISSION_TARGET`(0.1) ~ `MAX_MISSION_TARGET`(100,000)
- 최소 1개 이상의 아비투스에서 행동양식+미션을 선택해야 저장 가능
- **최초 설정 후 수정 불가** (`GOALS_ALREADY_SET` 에러, `guide.html` 2번 섹션에도 명시)
- 독서/공부/주간회고는 공통 과제라 이 목록에서 자동 제외됨 (`COMMON_TASK_STAT_NAMES`)

이번 범위에서 할 일은 새 로직 추가가 아니라, 온보딩 흐름 안에서 "자본 선택 다음 스텝"으로
자연스럽게 이어지도록 화면을 나누는 것 — 5번 시나리오와 마찬가지로 분리 여부 ⚠️ 확인 필요.

## 9. 첫 인증 실습

실제 인증 로직(`MissionCard.tsx`, `CameraCapture.tsx`)은 이미 완성되어 있어요: 카메라 실시간
촬영만 허용(갤러리 업로드 불가 — 사진 재사용 방지), 촬영 즉시 `analyzeVisionPhoto`로 AI 검증,
`PHOTO_NOT_FROM_TODAY`/`PHOTO_DATE_UNKNOWN` 같은 에러 코드까지 갖춰져 있어요.

| 단계 | 화면/동작 |
|---|---|
| 1 | 미션 설정 완료 직후, 실제 `/record`로 보내기 전에 "연습 인증" 스텝 삽입 |
| 2 | 실제 미션이 아닌 연습용 더미 카드로 카메라 촬영 → 업로드 → AI 확인까지 동일한 컴포넌트(`CameraCaptureModal`)를 그대로 재사용해서 보여주기 |
| 3 | 연습 데이터는 서버에 저장하지 않음(진짜 기록과 섞이면 안 되니까) — 프론트 로컬 상태로만 시뮬레이션 |
| 4 | "이렇게 매일 인증하시면 돼요!" 완료 카피 후 `/dashboard`(또는 `/record`)로 이동 |

**연동 지점**: 백엔드 변경 없이 프론트에서만 `CameraCaptureModal`을 재사용해 만들 수 있는,
9개 중 가장 구현 비용이 낮은 시나리오예요.
