# 어드민 사이트 기능 요구사항 (검수용)

이번 작업으로 구현된 `/admin` 관리자 사이트의 기능을 정리합니다. 검수 후 빠졌거나 다르게
동작해야 하는 부분을 알려주시면 바로 반영할게요.

## 1. 접근 권한

- 같은 DB, 같은 서버를 그대로 사용해요. `users` 테이블에 `role`(USER/ADMIN) 컬럼을
  추가했고, 로그인/회원가입 시 닉네임이 `ADMIN_NICKNAMES` 환경변수(콤마 구분)에 있으면
  자동으로 ADMIN 권한이 부여돼요.
- `/api/admin/**` 은 서버에서 ADMIN 권한만 허용하도록 막혀 있고, 프론트엔드 `/admin`
  라우트도 ADMIN이 아니면 대시보드로 돌려보내요. 내비게이션 바에는 ADMIN 계정에게만
  "관리자" 메뉴가 보여요.

## 2. 지원자 / 참가자 관리

- 아직 기수가 배정되지 않은 회원은 "지원자" 탭에 신청일 순으로 나타나요.
- 지원자에게 기수(예: "1기", "2기", "3기" - 자유 텍스트라 새 기수를 코드 수정 없이 바로
  쓸 수 있어요)를 배정하면 "참가자" 탭으로 이동해요.
- 참가자 탭은 기수별로 필터링해서 볼 수 있고, "전체 기수"로도 볼 수 있어요.

## 3. 주간 활동 · 환급 관리 (핵심 기능)

- 주 단위(월~일)로 이전 주/다음 주를 이동하며 조회해요.
- 참가자별로 "성공일수"(7일 중 며칠을 성공했는지)를 보여줘요. 하루 판정은 그날 활성화된
  미션을 전부 완료하면 1일, 일부만 완료하면 0.5일, 하나도 못 하면 0일로 계산해요
  (요청하신 "완료=1일, 미완=0.5일" 규칙을 기존 미션 완료 데이터로 근사한 값이에요).
- 6일 이상 성공하면 자동으로 "환급 대상"으로 표시돼요 (예치금 100,000원의 1/4인
  25,000원 규칙 기준).
- 관리자가 실제로 25,000원을 지급했는지 체크박스로 표시하고 지급일이 기록돼요. 이
  대상/지급 여부 자동 판정은 참고용이고, 최종 지급 여부는 항상 관리자가 직접 체크해요.
- 현재 화면(선택한 기수/주)을 CSV(엑셀에서 바로 열림)로 내보낼 수 있어요.

## 4. 주간 MVP

- 관리자가 기수·주 단위로 MVP를 지정할 수 있어요. 같은 기수/같은 주에 새 MVP를 지정하면
  이전 MVP는 자동으로 교체돼요.
- **주의**: MVP로 지정하면 "스탯을 올려준다"는 보너스 자체는 아직 자동으로 적용되지
  않아요. 지정 기록만 남고, 실제 보너스 점수는 아래 "점수 보정" 기능으로 관리자가 직접
  입력해야 해요.

## 5. 점수 보정 (컴플레인 대응)

- 참가자별로 총점 또는 특정 자본(신체/경제/문화/지식/언어/심리/상징)에 대해 +/- 점수를
  사유와 함께 기록할 수 있어요 (MVP 보너스, 컴플레인 정정 등).
- 기록은 삭제(롤백) 가능하고, 삭제 이력 없이 바로 지워지는 방식이에요 (수정이 아니라
  삭제로 되돌리는 구조).
- **주의**: 이 보정 내역은 현재 기록·조회용이고, 대시보드/주간 리포트에 표시되는
  실제 점수 계산에는 아직 자동으로 합산되지 않아요. 사용자 화면 점수에 실제로
  반영하려면 채점 엔진(DailyRecordService)에 추가로 연동하는 작업이 필요해요 - 이번
  범위에서는 관리자가 상황을 기록하고 참고하는 용도까지만 구현했어요.

## 6. 아직 포함되지 않은 것 (다음 단계 후보)

- MVP 보너스 / 점수 보정을 사용자 대시보드 실제 점수에 자동 반영
- 지원 신청 자체를 별도 "지원서" 데이터로 받는 흐름 (현재는 회원가입 = 지원자로 시작하고,
  관리자가 기수를 배정하면 참가자가 되는 구조예요)
- 완주 환급(4주 전액), 최종 엔딩 리포트, 엔딩 캐릭터 배정
- 닉네임+PIN 로그인, 초대장 페이지

## 7. 실서비스 반영 전 확인해주세요

- DB 마이그레이션: `backend/src/main/resources/db/migration_2026_admin.sql` 을 운영
  DB에 한 번 실행해야 새 컬럼/테이블이 생겨요 (`schema.sql`은 DROP DATABASE로
  시작하는 처음 설치용 스크립트라 운영 DB에는 절대 재실행하면 안 돼요).
- 환경변수: `ADMIN_NICKNAMES`(관리자로 쓸 닉네임, 콤마로 구분)를 배포 환경에
  설정해주세요.
- 로그인 세션이 하루 만에 끊기던 문제도 이번에 같이 고쳤어요 (JWT 유지 기간을 30일로
  늘리고, 세션이 만료되면 자동 로그아웃되도록 처리). 배포 환경에 `JWT_EXPIRATION_MINUTES`
  값이 따로 설정되어 있다면 같이 늘려주세요.
